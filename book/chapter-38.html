۱. وب چطور کار می‌کند

  1. مرورگر یک درخواست می‌فرستد: یک روش (GET، POST و مانند آن) و یک آدرس.
  2. برنامه شما تابع نمایی را انتخاب می‌کند که مسیرش با آن آدرس جور است.
  3. تابع یک پاسخ برمی‌گرداند: مقداری HTML یا JSON، به‌علاوه یک کد وضعیت مثل ۲۰۰ یا ۴۰۴ یا ۵۰۰.
  4. مرورگر آن را می‌کشد.
  5. و بعد همه چیز را فراموش می‌کند. HTTP حافظه ندارد، و نشست و کوکی دقیقاً برای همین وجود دارند.

۳. آدرس متغیر، url_for و ۴۰۴

@app.route('/user/<username>')
def profile(username: str) -> str:
    '''A missing user is a 404, not a crash.'''
    if username not in USERS:
        abort(404)
    return f'<h1>{USERS[username]}</h1><p>username: {username}</p>'


@app.route('/post/<int:post_id>')
def post(post_id: int) -> str:
    '''`<int:...>`: post_id really is an int here.'''
    title = POSTS.get(post_id)
    if title is None:
        abort(404)
    # post_id is a real int, so arithmetic works without any conversion.
    return (f'<h1>{title}</h1>'
            f'<p>post {post_id}; the next one would be {post_id + 1}</p>')


@app.route('/old-home')
def old_home():
    '''A page that moved: send the browser to the new address.'''
    return redirect(url_for('home'))


@app.errorhandler(404)
def not_found(error):
    '''Our own 404 page. The second value is the HTTP STATUS CODE.'''
    return ('<h1>404 - not found</h1>'
            f'<p><a href="{url_for("home")}">back home</a></p>'), 404

شرح مثال

  • <int:post_id> ارزش زیادی دارد: آدرس /post/abc یک ۴۰۴ تمیز می‌گیرد و اصلاً به کد شما نمی‌رسد.
  • url_for('نام تابع', آرگومان‌ها) آدرس را از روی نام تابع می‌سازد. هرگز لینک را دستی ننویسید: مسیر را یک بار عوض کنید و همه لینک‌ها دنبالش می‌آیند.
  • نسخه اصلی این درس مستقیم usernames[username] می‌نوشت. کاربر ناشناس یعنی KeyError و بازدیدکننده یک ۵۰۰ می‌گرفت، که یعنی «برنامه‌نویس اشتباه کرده». کاربری که وجود ندارد اشتباه نیست؛ پاسخ صادقانه‌اش ۴۰۴ است. کار abort(404) همین است.
  • @app.errorhandler(404) صفحه خطای خودتان را جایگزین می‌کند. عدد دوم در return همان کد وضعیت است.

۴. قالب‌های Jinja2

برگرداندن HTML از داخل رشته پایتون، بعد از سه خط از دست می‌رود. Flask از Jinja2 استفاده می‌کند: یک فایل HTML که در آن سوراخ‌هایی هست. قالب‌ها در پوشه‌ای به نام templates/ کنار app.py می‌نشینند و این نام ثابت است. 

@app.route('/students')
def students():
    return render_template('students.html', students=STUDENTS,
                           passing_mark=10)


@app.route('/empty')
def empty():
    '''The same template with an empty list: see the {% else %} of the loop.'''
    return render_template('students.html', students=[], passing_mark=10)

گریز خودکار، و حفره XSS

Jinja به طور خودکار محتوای متغیرها را بی‌خطر می‌کند: یک script که کاربر تایپ کرده، به متن ساده تبدیل می‌شود و اجرا نمی‌شود. اگر این محافظ را با فیلتر safe روی داده‌ای که کاربر فرستاده خاموش کنید، در همین مرحله یک حفره XSS ساخته‌اید. قاعده ساده است: هرگز safe را روی داده‌ای که از کاربر آمده نگذارید.

۵. ارث‌بری قالب و فایل ایستا

نوشتن سرصفحه و منو و پاصفحه در ده فایل یعنی ده جا برای تغییر دادن. راه درست، یک قالب پایه است که بقیه از آن ارث می‌برند. 

<head>
    <meta charset="UTF-8">
    {# A block with a DEFAULT value: a child page may override the title. #}
    <title>{% block title %}{{ site_name }}{% endblock %}</title>

    {# url_for('static', ...) -- never write the path by hand. #}
    <link rel="stylesheet"
          href="{{ url_for('static', filename='style.css') }}">
</head>
<body>
    <header>
        <h1>{{ site_name }}</h1>
        <nav>
            <a href="{{ url_for('home') }}">Home</a>
            <a href="{{ url_for('courses') }}">Courses</a>
        </nav>
    </header>

    <main>
        {# The hole every child page fills. #}
        {% block content %}{% endblock %}
    </main>
</body>

شرح مثال

  • هر صفحه فرزند با {% extends 'base.html' %} شروع می‌شود و فقط بلوک‌ها را پر می‌کند.

  • فایل‌های ایستا (CSS، تصویر، جاوااسکریپت) در پوشه static/ می‌روند و همیشه با url_for('static', filename=...) صدا زده می‌شوند.
  • @app.context_processor متغیری مثل site_name را در همه قالب‌ها در دسترس می‌گذارد، بدون اینکه در هر render_template پاسش بدهید.

۶. فرم‌ها و قاعده PRG

def validate(form) -> tuple[dict, list[str]]:
    '''Clean the fields and collect every problem, not just the first one.'''
    data = {
        'name': form.get('name', '').strip(),
        'email': form.get('email', '').strip(),
        'course': form.get('course', ''),
        'sessions': form.get('sessions', '').strip(),
        'newsletter': 'newsletter' in form,      # a checkbox is present or not
    }
    errors = []

    if len(data['name']) < 3:
        errors.append('The name must be at least 3 characters long.')
    if not EMAIL_PATTERN.match(data['email']):
        errors.append('That does not look like an e-mail address.')
    # Never trust a <select>: the browser is not the only thing that can POST.
    if data['course'] not in COURSES:
        errors.append('Please choose a course from the list.')
    if not data['sessions'].isdigit() or not 1 <= int(data['sessions']) <= 20:
        errors.append('The number of sessions must be between 1 and 20.')

    return data, errors


@app.route('/', methods=['GET', 'POST'])
def register():
    '''One address, two methods: show the form, then receive it.'''
    if request.method == 'POST':
        data, errors = validate(request.form)

        if errors:
            for message in errors:
                flash(message, 'error')
            # Give the form back WITH what the visitor already typed.
            return render_template('register.html', courses=COURSES,
                                   data=data)

        data['sessions'] = int(data['sessions'])
        REGISTRATIONS.append(data)
        flash(f'Thank you {data["name"]}, you are registered.', 'success')
        # POST / Redirect / GET: F5 now reloads a harmless page.
        return redirect(url_for('registrations'))

    # GET: an empty form.
    return render_template('register.html', courses=COURSES, data={})

قاعده POST / Redirect / GET

بعد از یک POST موفق، هرگز صفحه را رندر نکنید؛ هدایت کنید. وگرنه مرورگر هنوز همان POST را در دست دارد و زدن F5 فرم را دوباره می‌فرستد: ثبت‌نام دوم، پرداخت دوم. هدایت کردن، آخرین کار را به یک GET بی‌خطر تبدیل می‌کند. پیام flash() هم برای همین است: پیام را نگه می‌دارد تا صفحه بعدی نشانش دهد.

۷. نشست و کوکی

HTTP حافظه ندارد. هر درخواست تنها می‌آید و سرور نمی‌داند کسی که /profile را می‌خواهد همان کسی است که یک ثانیه پیش فرم ورود را پر کرد. پاسخ، کوکی است. 

session['username'] = 'sara'      # write
session.get('username')           # read
session.pop('username', None)     # forget
session.clear()                   # forget everything

نشست، یک دیکشنری درون کوکی

آنچه باید درباره نشست بدانید

  • کوکی با app.secret_key امضا می‌شود، پس کسی نمی‌تواند بدون لو رفتن تغییرش دهد. ولی فقط base64 است، پس هر کسی می‌تواند بخواندش. هرگز رمز عبور یا شماره کارت یا هر چیز خصوصی در نشست نگذارید.
  • اگر کلید مخفی عوض شود، همه نشست‌ها همان لحظه باطل می‌شوند.
  • همه‌اش در مرورگر بازدیدکننده زندگی می‌کند، پس کوچک نگهش دارید.
  • کلید مخفی، مثل توکن ربات فصل سی و هفتم، نباید در کد یک سایت واقعی نوشته شود. از متغیر محیطی بخوانیدش.

۸. رمز عبور و login_required

def login_required(view):
    '''A decorator that sends anonymous visitors to the login page.'''
    @functools.wraps(view)          # keep the name of the wrapped function
    def wrapper(*args, **kwargs):
        if 'username' not in session:
            flash('Please log in first.', 'error')
            # `next=` remembers where the visitor wanted to go.
            return redirect(url_for('login', next=request.path))
        return view(*args, **kwargs)
    return wrapper


@app.route('/login', methods=['GET', 'POST'])
def login():
    if request.method == 'POST':
        username = request.form.get('username', '').strip().lower()
        password = request.form.get('password', '')

        user = USERS.get(username)
        # ONE message for both cases: saying "no such user" would tell an
        # attacker which names exist.
        if user is None or not check_password_hash(user['password_hash'],
                                                   password):
            flash('Wrong user name or password.', 'error')
            return render_template('login.html', username=username)

        # A new session id at login: it closes the "session fixation" hole.
        session.clear()
        session['username'] = username

        # Never redirect to any address the visitor sends us: an absolute URL
        # here would be an "open redirect" straight to a phishing page.
        target = request.args.get('next', '')
        if not target.startswith('/') or target.startswith('//'):
            target = url_for('profile')
        return redirect(target)

    return render_template('login.html', username='')

هرگز رمز عبور را ذخیره نکنید

درهم رمز را ذخیره کنید: generate_password_hash('1234') چیزی مثل scrypt:32768:8:1$xYz... می‌سازد، و check_password_hash(hash, typed) درست یا نادرست می‌دهد. درهم را نمی‌شود به رمز برگرداند، پس پایگاه داده دزدیده‌شده، رمز همه کاربران را به مهاجم نمی‌دهد. کتابخانه werkzeug همراه Flask می‌آید، پس در همین مرحله داریدش.

سه نکته امنیتی در همین چند خط

  • برای «کاربر وجود ندارد» و «رمز غلط است» یک پیام بدهید. پیام جداگانه به مهاجم می‌گوید کدام نام کاربری واقعی است.
  • session.clear() هنگام ورود، حفره تثبیت نشست را می‌بندد.
  • هرگز به هر آدرسی که بازدیدکننده می‌فرستد هدایت نکنید. یک آدرس مطلق در next یعنی هدایت باز مستقیم به یک صفحه فیشینگ.
  • @functools.wraps در دکوراتور فراموش نشود: Flask توابع نما را با نامشان می‌شناسد و بدون آن، دو نما هر دو wrapper نام می‌گیرند و برنامه بالا نمی‌آید.

def read_payload() -> tuple[dict | None, tuple | None]:
    '''Return (data, error_response). Exactly one of the two is None.'''
    # silent=True -> None instead of an exception when the body is not JSON.
    payload = request.get_json(silent=True)
    if not isinstance(payload, dict):
        return None, (jsonify(error='the body must be a JSON object'), 400)
    return payload, None


@app.route('/api/books/<int:book_id>', methods=['GET'])
def get_book(book_id: int):
    if book_id not in BOOKS:
        return jsonify(error=f'no book with id {book_id}'), 404
    return jsonify(with_id(book_id))


@app.route('/api/books', methods=['POST'])
def create_book():
    global next_id

    payload, error = read_payload()
    if error:
        return error

    title = str(payload.get('title', '')).strip()
    if not title:
        return jsonify(error='"title" is required'), 400

    book_id = next_id
    next_id += 1
    BOOKS[book_id] = {'title': title, ...}
    # 201 Created, and the address of the new thing in the Location header.
    return jsonify(with_id(book_id)), 201, {
        'Location': f'/api/books/{book_id}'}


@app.errorhandler(404)

  • نسخه اصلی این درس مستقیم payload['title'] می‌نوشت. اگر مشتری فیلدی را جا بیندازد یا اصلاً JSON نفرستد، نتیجه‌اش KeyError است و یک صفحه ۵۰۰. ولی فیلد جاافتاده اشتباه مشتری است: ۴۰۰.
  • get_json(silent=True) به جای استثنا، None می‌دهد؛ دقیقاً همان چیزی که برای بررسی لازم داریم.
  • بسته‌بندی فهرست در یک شیء (count و books) جا برای اضافه کردن «صفحه بعدی» باقی می‌گذارد، بدون شکستن همه مشتری‌ها.
  • یک API حتی هنگام شکست هم باید JSON بدهد، نه صفحه HTML. برای همین errorhandler هم jsonify برمی‌گرداند.

۱۱. Flask-SQLAlchemy

همان SQLAlchemy فصل سی و دوم، این بار داخل یک سایت. Flask-SQLAlchemy لایه نازکی روی آن است که db.session و db.Model را از قبل به برنامه گره می‌زند. 

class Base(DeclarativeBase):
    '''The base class every model inherits from (SQLAlchemy 2 style).'''


db = SQLAlchemy(model_class=Base)

app = Flask(__name__)
app.config['SQLALCHEMY_DATABASE_URI'] = 'sqlite:///library.db'

class Author(db.Model):
    __tablename__ = 'author'

    id: Mapped[int] = mapped_column(primary_key=True)
    name: Mapped[str] = mapped_column(String(100), nullable=False)

    # One author has many books. `back_populates` connects the two sides;
    # `cascade` deletes the books of an author we delete.
    books: Mapped[list['Book']] = relationship(
        back_populates='author', cascade='all, delete-orphan')

۱۲. پروژه: دفترچه یادداشت

پروژه پایانی این فصل، یک برنامه یادداشت با دسته‌بندی، جست‌وجو، چهار عمل اصلی و یک API است. مهم‌ترین درسش دو الگوست که هر پروژه Flask بعد از سی مسیر به آنها نیاز پیدا می‌کند: کارخانه برنامه و بلوپرینت.

چرا این تابع اضافه ارزشش را دارد

  • پیکربندی یک آرگومان می‌شود، پس همان کد می‌تواند با پایگاه داده دیگری اجرا شود: یک پایگاه داده واقعی، یک موقتی، یکی برای هر برنامه‌نویس.
  • صرفاً به خاطر import شدن ماژول، هیچ اتفاقی نمی‌افتد.
  • گره وارد کردن دایره‌ای باز می‌شود: models و routes هرگز app را وارد نمی‌کنند.

ساختار پروژه سه فایل پایتون دارد که هر کدام یک کار می‌کنند: models.py فقط جدول‌ها، routes.py فقط مسیرها در قالب یک بلوپرینت، و app.py که همه را به هم وصل می‌کند. همان لایه‌بندی فصل سی و پنجم، این بار در وب. 

class Note(db.Model):
    __tablename__ = 'note'

    id: Mapped[int] = mapped_column(primary_key=True)
    title: Mapped[str] = mapped_column(String(120), nullable=False)
    body: Mapped[str] = mapped_column(Text, nullable=False, default='')

    # A note without a category is allowed, so the column may be NULL.
    category_id: Mapped[int | None] = mapped_column(
        ForeignKey('category.id'), nullable=True)
    category: Mapped[Category | None] = relationship(back_populates='notes')

    # server_default=func.now(): the DATABASE fills it in, so the value is
    # right even for a row inserted by hand in another program.
    created_at: Mapped[datetime] = mapped_column(
        DateTime, server_default=func.now())
    updated_at: Mapped[datetime] = mapped_column(
        DateTime, server_default=func.now(), onupdate=func.now())

    def to_dict(self) -> dict:
        '''The shape the JSON API sends out.'''
        return {'id': self.id,
                'title': self.title,
                'body': self.body,
                'category': self.category.name if self.category else None,
                'created_at': self.created_at.isoformat()}

تمرین‌های فصل سی و هشت

  1. سایتی با سه صفحه بسازید: خانه، درباره ما و تماس، با یک منوی مشترک در قالب پایه.
  2. مسیری بسازید که عددی بگیرد و جدول ضرب آن عدد را در یک جدول HTML نشان دهد.
  3. صفحه ۴۰۴ و ۵۰۰ اختصاصی برای سایتتان بنویسید.
  4. فهرست دانشجویان را از یک فایل JSON بخوانید و با for و if در قالب نمایش دهید.
  5. یک فرم نظرسنجی بسازید که همه فیلدها را اعتبارسنجی کند، خطاها را با flash نشان دهد، و بعد از ثبت موفق هدایت کند.
  6. جست‌وجوی ?q= روی همان فهرست پیاده کنید.
  7. ورود کاربر با رمز درهم‌شده و دکوراتور @login_required بسازید و صفحه پروفایل را محافظت کنید.
  8. به سایتتان صفحه خروج اضافه کنید و مطمئن شوید نشست کاملاً پاک می‌شود.
  9. یک REST API برای «کارهای امروز» بنویسید با هر شش عمل و کدهای وضعیت درست.
  10. برای همان API یک مشتری با requests بنویسید که timeout دارد و ۴۰۴ را از ۵۰۰ تشخیص می‌دهد.
  11. پروژه یادداشت را با یک مدل تازه گسترش دهید: برچسب‌ها، با رابطه چندبه‌چند.
  12. به پروژه یادداشت، صفحه‌بندی اضافه کنید: ده یادداشت در هر صفحه.
  13. توضیح دهید چرا debug=True روی سرور واقعی خطرناک است و دقیقاً چه چیزی را در اختیار مهاجم می‌گذارد.
  14. توضیح دهید چرا فیلتر safe روی داده‌ای که کاربر نوشته، یک حفره امنیتی است. یک نمونه ورودی بنویسید که حمله را نشان دهد.
